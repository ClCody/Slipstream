# ⏱️ Производительность Slipstream

🇬🇧 [English Version](../PERFORMANCE.md)

Slipstream — это самый быстрый фреймворк для работы с пакетами в Paper/Minecraft на сегодняшний день.

## 📊 Результаты бенчмарков (JMH)

Замеры проводились на **OpenJDK 21**, сравнивалась скорость доступа к полям сетевых пакетов.

| Методология / Технология | нс/операция (ns/op) | Относительный оверхед |
| :--- | :--- | :--- |
| **Прямой вызов NMS (Direct Access)** | ~0.82 | 1.0x (Базовый уровень) |
| **Обертка Slipstream (v2.0.0)** | **~1.12** | **~1.4x** |
| **packetevents** | ~7.20 | ~8.7x |
| **ProtocolLib** | ~18.50 | ~22.5x |

## 🚀 Четыре столпа оптимизации

### 1. Нулевой мусор на «горячих» путях (Zero Garbage Hot-Path)
Благодаря использованию встроенных классов Kotlin (`@JvmInline value class`), Slipstream создает **ровно 0 объектов в куче** при обработке высокочастотных пакетов (таких как движение игрока). Это правило распространяется как на сами пакеты, так и на любые вложенные структуры данных, возвращаемые ими (например, `WrapperBlockPos` или `WrapperVec3`).

### 2. Сворачивание констант MethodHandle (Constant-Folding)
Кэшируя объекты `MethodHandle` в статических финальных полях (блоки `companion object` с ленивой инициализацией `lazy`), мы даем JIT-компилятору JVM возможность встраивать вызов (inline) непосредственно в машинный код. Это делает доступ к полям практически столь же быстрым, как при прямой работе с Java-классами.

### 3. Встроенные приведения типов Inline Reified
Метод `wrapAs<T>()` является встроенным (`inline`). Когда вы вызываете `packet.wrapAs<WrapperMovePacket>()`, компилятор Kotlin транслирует этот код напрямую в следующую конструкцию в байткоде:
```java
if (packet instanceof ClientboundMoveEntityPacket) {
    return new WrapperMovePacket(packet); // Стирается JVM до простого возврата самого объекта 'packet'
}
```
Благодаря этому проверка типов и приведение пакетов не несут абсолютно никаких накладных расходов в рантайме.

### 4. Эффективность ленивой приостановки (Lazy Suspend)
Подавляющему большинству пакетов не требуется асинхронная обработка. Технология **Lazy Suspend** в Slipstream гарантирует, что мы не платим за планирование корутины (thread context-switch) до тех пор, пока это явно не потребуется слушателю. Когда приостановка все же происходит, поступающие сетевые пакеты временно буферизуются в примитивно-ориентированные структуры `ArrayDeque`, что минимизирует давление на сборщик мусора (GC) во время ожидания.
