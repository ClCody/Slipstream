# 🏗️ Архитектура Slipstream (v2.0.0)

🇬🇧 [English Version](../ARCHITECTURE.md)

Slipstream разработан для достижения максимальной производительности в условиях высокочастотной обработки сетевых пакетов. В версии 2.0.0 фреймворк разделен на **мультимодульную** структуру, что обеспечивает строгую типизацию на этапе компиляции при сохранении высочайшей производительности в рантайме.

## 📦 Мультимодульная структура

1. **`slipstream-generator`**: Автономная утилита сборки. Использует библиотеку `ClassGraph` для сканирования классов NMS (Netty/Minecraft Server) во время компиляции и динамически генерирует Kotlin-обертки для всех доступных пакетов и вложенных структур.
2. **`slipstream-generated`**: Выходной модуль, содержащий более 500+ сгенерированных оберток `value class`. Такая изоляция предотвращает попадание сырых классов NMS в публичный API ядра.
3. **`slipstream-core`**: Основная логика фреймворка, содержащая обработчики пайплайна Netty, очереди ленивой приостановки (lazy suspend) и систему приоритетов событий.

## 🛠️ Ключевые принципы

### 1. Отсутствие рефлексии в рантайме (Zero-Reflection)
Мы полностью избегаем использования `java.lang.reflect` на «горячих» путях обработки пакетов. Вместо этого используются `MethodHandles`, которые оптимизируются (constant-folded) C2 JIT-компилятором JVM до уровня прямых вызовов методов.

### 2. Нулевые аллокации (Zero-Allocation / Value Classes)
Slipstream оборачивает пакеты NMS во встроенные классы Kotlin (`@JvmInline value class`). Эти обертки полностью стираются компилятором на этапе сборки.
*Новое в версии 2.0.0:* Гарантия нулевых аллокаций теперь распространяется и на вложенные структуры NMS (такие как `BlockPos`, `Vec3`, `ItemStack`).

### 3. Чистое пространство имен через Inline Reified
Вместо захламления глобального пространства имен `Any` сотнями методов вроде `isPacket()`, Slipstream 2.0.0 использует единственную встроенную функцию расширения:
```kotlin
inline fun <reified T : Any> Any.wrapAs(): T?
```
Поскольку функция является `inline reified`, компилятор Kotlin выполняет оптимизацию удаления мертвого кода (DCE). В рантайме это превращается в простую проверку `instanceof` — нулевые накладные расходы и отсутствие создания промежуточных объектов-оберток до тех пор, пока проверка типа не завершится успешно.

### 4. Сначала корутины и ленивый Suspend (Coroutine-First & Lazy Suspend)
Slipstream гарантирует строгое сохранение порядка пакетов игрока при одновременной поддержке асинхронной обработки.
Для минимизации накладных расходов применяется стратегия **ленивой приостановки (Lazy Suspend)**:
- Slipstream запускает корутину только в том случае, если зарегистрированный `SuspendablePacketListener` явно выражает интерес к данному типу пакета.
- Если ни один асинхронный слушатель не заинтересован в пакете, он продолжает движение по конвейеру Netty синхронно, без переключения контекста потоков.

### 5. Поддержка Java Records
Современный Minecraft (1.20+) активно использует Java Records. Генератор Slipstream автоматически распознает метод `isRecord()` и связывает свойства обертки напрямую с компонентами записи, минуя стандартные правила геттеров/сеттеров. Для изменения иммутабельных записей генератор создает метод `.copy()`, использующий кэшированный `MethodHandle` конструктора записи.

### 6. Нативная интеграция с маппингами Paper (Mojang)
В средах 1.21+ сервер Paper использует официальные маппинги Mojang прямо во время работы. Slipstream задействует это преимущество, запрашивая методы и поля по их официальным Mojang-именам. Это исключает любые задержки на перемаппинг полей в рантайме.

## 📡 Визуализация конвейера Netty (Pipeline)
```text
[ Сетевой интерфейс (Network Interface) ]
         |
         v
[ Дефолтные хэндлеры Netty ]
         |
         v
[ slipstream_handler ]  <-- НАШ ХЭНДЛЕР ТУТ
         |                   - Ожидание пакетов / Awaiters (O(1))
         |                   - Синхронные слушатели (в порядке приоритетов)
         |                   - Ленивый Suspend (при необходимости)
         v
[ packet_handler ]      <-- Внутренний обработчик Minecraft
         |
         v
[ Игровая логика сервера ]
```
